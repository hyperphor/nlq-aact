# nlq-aact

A small standalone NL-query demo app over [AACT](https://aact.ctti-clinicaltrials.org)
(Aggregate Analysis of ClinicalTrials.gov), built on `com.hyperphor/nlq`'s `:postgres`
source. 

[Live version](https:://aact.hyperphor.com)

## Status

Backend + a minimal frontend: three tabs (about / NL query / schema browser), The NL_query tab is `hyperphor.nlq.frontend.
sql-query/ui` (the real query-UI component the library ships) called against the single
`"AACT"` project; the schema tab is an iframe onto the generated Alzabo schema doc.

## Running

```
export AACT_USER=... AACT_PASSWORD=...   # AACT read-only reporting account
lein run 8090
```
then open `http://localhost:8090/`. Or hit the API directly:
```
curl 'http://localhost:8090/api/qbox/query?id=sql&project=AACT&query=Show+full+studies+table'
```

For frontend dev iteration, `npm install` once, then either `lein shadow watch app`
(hot-reload) or `lein shadow release app` (optimized, what the `:uberjar` profile's
`prep-tasks` also run).


## Query logging 

`resources/config.edn`'s `:nlq-log` entry, if present, logs every NL query to a
DynamoDB table (`hyperphor.nlq.generate/record`, dispatching on `:nlq-log`'s `:type`
-- `:dynamo` here; `:bigquery` is the other backend the library supports, what OKC
uses). Absent entirely, logging is a silent no-op -- not required to run the app.

```
export AWS_ACCESS_KEY_ID=... AWS_SECRET_ACCESS_KEY=...   # IAM user/role scoped to
                                                            # PutItem+Scan on just the
                                                            # log table below, nothing else
lein run 8090
```

Same pattern as `AACT_USER`/`AACT_PASSWORD`: env vars, never literal credentials in a
file. The DynamoDB table itself (`nlq-log` by default, `us-west-2`) isn't
provisioned by this app -- create it once by hand (String partition key named
`"uuid"`) before enabling logging. See `hyperphor.nlq.logging.dynamo` (in the `nlq`
library) for the write/scan implementation -- adapted from `pici/pimento`'s own
DynamoDB query logging.

## Schema regeneration

`resources/aact/schema.alz.edn` is generated by `hyperphor.nlq-aact.schema-gen/
regenerate-schema` against a live AACT connection (currently checked in from a real run,
2026-08-19 -- ~60s, mostly spent on per-column enum-candidate scans against
`pg_stats`/`pg_constraint`). Re-run it whenever AACT's schema changes or the data
dictionary CSV is refreshed:

```clojure
(require '[hyperphor.way.config :as config])
(config/read-config "config.edn")
(require '[hyperphor.nlq-aact.schema-gen :as sg])
(sg/regenerate-schema)
```
